# Project rules

- `scripts/content/` has its own `AGENTS.md`; read it before changing files there.

- Both clients use PostHog only after a Settings opt-in (no launch overlay), with shared semantic events/normalized paths; account-ID identity resets on changes. No replay, auto-text, ads, credentials, private text, OAuth URLs, video capture or duplicate purchase attribution. Why: safe comparable funnels.

- Two clients, one product: `mobile/` (Flutter) is the shipped Android app; the root TanStack app is its interactive prototype rendered in a phone frame. Every UI or rule change lands in both, Flutter first. Why: the user previews on web but ships the APK.
- Founder settings are read-only with offline fallback, edited by privileged tools. Trial warms data/notes/poster and blank WebView script cache, never hidden players/downloads. Why: safe control and separate cache.
- Business rules live only in `src/lib/logic.ts` and `mobile/lib/logic/logic.dart`, kept 1:1 with mirrored tests (`src/lib/logic.test.ts`, `mobile/test/logic_test.dart`) asserting identical values. Why: the two clients must behave the same.
- Design tokens are defined in `src/styles.css` and mirrored in `mobile/lib/theme/tokens.dart`; components use tokens only. Why: one visual language across clients.
- Optional packs from `scripts/content/publish_pack.ts` use public `content_settings`/`content` storage with content-addressed gzip. Both clients background-download, verify SHA-256/parse every file, activate only on next start when newer than bundle, otherwise fall back. Flutter caches/reuses identical bundled files; rules/tests are mirrored. Why: expand content without sacrificing offline defaults.
- App UI text is English in code wrapped in tr(); translations come from the reviewed catalog in `scripts/i18n/ui/` generated by `scripts/i18n/gen_strings.ts` into both clients (never hand-edit the generated catalogs); missing text falls back to English. Why: one catalog, no drift.
- Content stays English; other languages are overlays (`scripts/i18n/build_locale_packs.py` → bundled starter overlay + downloadable pack published by `publish_locale_packs.ts` to backend storage and R2, pointer in `content_settings.locale_packs`). Overlays apply only with a matching clipLocaleSig/count, download only with learning access, verify every file twice and activate next start. Why: translations can never mismatch clips and failures fall back to English.
- Saved words record the app language of their meaning (`glossLang`); screens show `savedGloss` (mirrored), falling back to the current dictionary meaning after a language switch. Why: learners who switch language never see a mix of old-language meanings.
- Videos play only through YouTube's official embedded player (IFrame API on web, youtube_player_iframe on Flutter), never downloaded, re-hosted or audio-extracted, never covered by overlays; show channel attribution and a Watch on YouTube link. Why: YouTube API terms.
- Feed players exist only for the active clip and the next one (`warm`: loaded and cued, never playing or reporting); trial previews and stand-alone players stay single. Pause before ready is queued, never sent. Why: fast swipes without extra video surfaces or early-command crashes; the embed ignores quality requests, so speed comes from warming.
- Feed loop/replay uses mirrored PlaybackLoopGuard; initial loading relies on the official start parameter, never a redundant seek or fixed-timer unlock. Why: stale/keyframe reports and re-seeks interrupt startup.
- Learner state is one JSON document (`mimi-state-v1`) stored locally and, when signed in, in `public.learner_state` (owner-only RLS), merged with `mergeState`; its `owner` scopes local progress to one account (`localStateFor`). Why: offline-first sync without leaking progress between accounts.
- Web app shell renders children only after hydration (AppFrame), so persisted state never causes SSR mismatches. Why: state lives in localStorage.
- Flutter purchases go through RevenueCat (`mobile/lib/services/billing.dart`, entitlement `premium`, offering `default`); `paywall.ts`/`paywall.dart` hold fallback prices that live store prices replace. The web prototype stays simulated. Why: one subscription backend for App Store and Play.
- Mirrored access rules gate learning; native sign-in awaits account-specific RevenueCat verification after sync, state replacement preserves device Premium, and active Premium skips acquisition onboarding/paywall. Ask verifies live entitlement server-side. Why: neither stale flags nor identity races may decide access.
- Direct-download APKs are split by ABI (arm64-v8a, armeabi-v7a, x86_64), size-reported in CI, and emulator E2E selects the x86_64 artifact; Play delivery stays AAB. Why: avoid bundling three runtimes on every phone without enabling unsafe R8 shrinking.
- APKs are built by GitHub Actions only after `flutter analyze` and `flutter test` pass; a second job runs `mobile/integration_test/` on an emulator via `.github/scripts/e2e.sh` (screenshots + logcat). Why: the shipped build must not fail.
- Release APKs are signed with one fixed key held only in GitHub Actions secrets (`ANDROID_KEYSTORE_*` → `KIZUKI_KEYSTORE*` env in `mobile/android/app/build.gradle.kts`); never commit a keystore. Why: updates need the same key; the repo is public.
- Android release builds keep R8 shrinking off (`mobile/android/app/build.gradle.kts`). Why: JNI-based plugins (shared_preferences) lose methods when shrunk and the app opens blank.
- The AI tutor (Ask Kizuki) runs only in the web app's server route `src/routes/api/public/ask.ts`, which requires a signed-in user's access token; both clients post the same AI SDK UI-message body, and the Android app calls the published origin (`AppConfig.apiOrigin`). Why: the AI key stays server-side and there is one tutor prompt.
- Web dev server ignores `mobile/**` (Flutter output reloads it).
- Word levels (1–4, Known, Ignored) are derived from the saved word's status + SRS card (`wordLevel`), never stored separately; picking a level reschedules the card (`withWordLevel`). Why: one source of truth, so reviews, Vocab counts and underlines can never disagree.
- Review answer cards show text context first and mount the official video player only in an explicitly opened sheet; familiarity controls group existing learning levels without resetting an already-learning card. Why: reviews stay focused and existing scheduling survives presentation simplification.
- Welcome-tour steps live in `src/lib/tour.ts` / `mobile/lib/data/tour.dart`; spotlight targets are `data-tour` attributes on web and `TourTargets` keys on Flutter, set only on the feed's active clip. Why: one tour definition per client, targets never point at off-screen clips.
- Ask Kizuki tour opens the real contextual sheet with a labelled local context/gloss example, never sending a question; the tour closes tutor/word sheets itself (web `closeSignal`, Flutter root-navigator pop) before their close events arrive, and a hand-closed card skips remaining card steps. Why: teach the tutor without spending a question or stranding learners in sheets.
- Tour tips fit the largest free area outside the visible spotlight and below Skip, with scrolling; the last step returns to feed. Why: guessed heights clipped text and covered controls.
- Learner schedules use formatWhen words, never formatInterval codes in review/word sheets. Why: "1m / 10m" confused learners.
- Flutter sheets (`showMimiSheet`) open on the root navigator, above the tab shell. Why: the web Sheet layers over the TabBar; inside the shell the floating tab bar covered cards and took their taps.

- Trial phone previews reuse the home ClipView and feed pager; only the settled clip creates a player, with no simulated transcript animations or geometry callbacks. Replace the founder route before opening trial to release its native video decoder. Why: real feed parity without retaining multiple video surfaces during onboarding.
- Native onboarding uses OnboardingBack (router dispatcher + PopScope), explicit previous-screen fallback with no stack, and preserves purchase-account gates. Why: Android Back must not close replacement routes accidentally.
- Generated starter clips use mirrored starterFeedOrder, showcase first: same onboarding order, then home until watched/watch limit, advanced-level guard; rankFeed stays personal. Why: curated first impression, then recommendations.
- Founder video: bundled captioned master is default; a valid https `founder_video_url` in onboarding_settings overrides it (Flutter caches an early download, web tries remote then bundled); clearing reverts. Contain framing; app captions only on failure. Why: server swap without a build, still instant/offline-safe.
- Meta SDK logs install/open + funnel events; RevenueCat Meta CAPI owns trial/purchase/renewal. Forward FB anonymous/device IDs; iOS plist ID collection defaults off until runtime ATT authorization. Why: no duplicate purchase source or pre-consent ID window.
- Store text: `store/listing.json`; approved images: `store/screenshots/` + `store/play/`. Use `scripts/stores/push_screenshots.py` for screenshots only; `push_listing.py` for full listings. Preserve approved artwork unless regeneration is requested. Why: avoid unrelated store changes.
- Help messages are inserted into `public.support_messages` (insert-only RLS for anon + signed-in, no client reads); limits come from `supportMessageError` in both logic files. Why: there is no support inbox yet, and customers are never emailed automatically.
- Privacy Policy and Terms copy lives only in `src/lib/legal.ts`; `mobile/lib/data/legal.dart` is generated from it (`bun scripts/legal/gen_legal_dart.ts`) and `src/lib/legal.test.ts` fails on drift. Why: store reviewers read the web URL and the in-app page, which must say the same thing.
- Static hosting pages use scripts/legal/export_website.ts; legal.ts owns copy. Why: no policy drift.
- Pinned-footer screens (onboarding steps, paywall) scroll their content inside a bottom-fading area (`scroll-fade` utility / `FadedScroll`) with the primary button outside it. Why: small phones and large system text must never push the main button or price off screen.

- Successful checkout/restore sets a local persisted purchase-account gate; only verified account completion clears it, and cloud merge never overrides it. Both clients block learning surfaces while pending. Why: payment must not be followed by a skippable or lost login step.
- Owner-only public.profiles stores identity display fields and learning preferences alongside learner_state; auth signup creates the row and sync updates it. Why: account profiles remain available across devices without an onboarding name prompt.
- Haptics go only through the semantic kinds in `src/lib/haptics.ts` / `mobile/lib/services/haptics.dart`, gated by `settings.haptics`; mascot/splash motion uses mirrored curves (`mascot-motion.ts` / `mascot_motion.dart`) and freezes under reduced motion. Why: identical feel, one vibration switch.
- Phones use native Google/Apple signInWithIdToken (mirrored signInProviders/signInMethod), never a browser; store-review password sign-in renders only when onboarding_settings.review_sign_in is true. Web keeps browser OAuth. Why: native journey; reviewers need hidden credentials.
- Widgets use offline snapshots without identity/tokens/notes; saved words opt-in, account changes replace data, expiry falls back to public words, taps stay guarded. iOS signing validates both App Group profiles. Why: safe native learning and releases.

- Backend is the project-owned external Supabase (ref gcoboyhfhadivheoilxp); web uses `src/lib/backend.ts` + `backend-config.ts`, Flutter uses AppConfig (`mobile/lib/services/config.dart`), server routes read those constants, not SUPABASE_* env. Why: founder owns the backend dashboard; no managed-cloud dependency.
- Flutter widget/async errors post a short record to insert-only public.app_errors (max 5/session, no learner text). Why: diagnose phone-only crashes.
